# Iteration 16：单公式复制到 Word/WPS 自带公式框

**版本：** userscript `1.15.9`；FastAPI 保持 `1.7.20`。本次统一网页选区、
网页译文卡、文档插件公式与文档插件译文的最终剪贴板输出；后台结果、内部
翻译/朗读和文档写回仍使用规范 LaTeX。Iteration 14 的轻量插件加载器登录启动、完整服务按需
启动方案继续保留。

## 1. 用户反馈与路径确认

用户将网页上的公式复制后，直接粘贴到 **WPS 自带公式编辑框**。截图中出现了
额外的外层方括号和矩阵空占位。用户手动删除这些内容后才能得到预期公式。

网页复制的原始样例：

```latex
\[ \begin{bmatrix} \dot{\theta}\\ \dot{\omega} \end{bmatrix} = \begin{bmatrix} \omega\\[2mm] \displaystyle\frac{g}{l}\left(\theta-\frac{\theta^3}{6}\right) +\frac{1}{ml^2}u \end{bmatrix} \]
```

这里需要区分两条处理路径：

| 粘贴位置 | 输入格式 | 解析方 |
|---|---|---|
| Word/WPS 自带公式编辑框 | 单个公式的裸 LaTeX | Office/WPS 的公式输入解析器 |
| 正文，随后点插件“转换为原生公式” | 正文与 `$...$` / `$$...$$` 公式 | 本地后台 Pandoc → DOCX/OMML |

原始样例经当前后台 DOCX/Pandoc 路径已生成两个正确的 `2 × 1` 矩阵；因此不能
把这次直接粘贴现象归因于后台生成多余矩阵列。修复针对的是复制内容与自带
公式编辑框输入约定的兼容性：外层 `\[...\]` 是文档中的显示公式标记，
`\\[2mm]` 是排版行距选项，都不需要作为公式本体传给编辑框。

## 2. 单公式复制规则

只有当完整待复制内容是 **一个可识别且带数学包装的公式、前后没有正文** 时，
最终复制出口才应用公式编辑框兼容处理：

1. 去掉最外层的一对 `$...$`、`$$...$$`、`\(...\)` 或 `\[...\]`。
2. 将 `bmatrix` 等带括号矩阵改写为等价的
   `\left...\begin{matrix}...\end{matrix}\right...`，保留数学括号和内容。
3. 在支持的矩阵、`array`、`aligned` 环境中，将行分隔符之后的合法长度选项
   去掉，例如 `\\[2mm]` 变为 `\\`；换行仍保留，不删除矩阵行或列。
4. 非法长度、普通方括号表达式和环境外的内容不当作排版选项删除。

MathJax/MathML/KaTeX 公式仍先经过现有语义提取和选区扩展；最终剪贴板变换
只作用于符合上述条件的单公式。包含正文或多个公式的内容继续使用规范
`$...$` / `$$...$$`，以保留正文和公式边界。适用的最终复制出口包括：

- 网页浮动工具条的 **Copy**；
- 网页译文卡的 **Copy**；
- Word/WPS 控制器 `copySelectionAsLatex`，包括 WPS PDF 识别后的复制；
- 文档插件的译文复制。

后台 `result.latex`、内部翻译/朗读和文档写回继续保留规范包装。公式复制
控制器额外返回 `clipboard_text`，用于查看实际写入剪贴板的兼容文本；不会
用它覆盖规范结果。

样例的兼容输出形态如下：

```latex
\left[\begin{matrix}
\dot{\theta} \\
\dot{\omega}
\end{matrix}\right]
=
\left[\begin{matrix}
\omega \\
\displaystyle\frac{g}{l}\left(\theta-\frac{\theta^3}{6}\right)+\frac{1}{ml^2}u
\end{matrix}\right]
```

输出仍是 LaTeX 纯文本。兼容处理不调用大模型，也不把公式转为图片。

## 3. 使用与升级

### 一个公式，直接粘贴进自带公式框

1. 在 Tampermonkey 中安装或更新到 `tts-userscript.js` **`1.15.9`**。
2. 刷新来源网页，选中一个完整公式。
3. 点击本脚本浮动工具条的 **Copy**。
4. 在 Word/WPS 中进入自带公式编辑框，使用 LaTeX 输入模式粘贴并转换。

网页自带的“复制公式”按钮不经过本脚本，复制结果仍可能包含 `\[...\]`
或 `\\[2mm]`。仓库中的脚本和 Tampermonkey 已安装副本也是两份内容，更新
项目文件不会自动替换浏览器副本。发布前本地验证可在 Tampermonkey 编辑器
中粘贴完整的本地脚本并保存；发布后再使用“检查用户脚本更新”，核对实际
安装版本。不能仅根据 README 的版本号认定浏览器已经升级。文档插件的共享
脚本更新后，关闭并重新打开任务窗格以载入新版本；其公式复制与译文复制也
应用相同规则。

### 正文带公式，或一次复制多个公式

1. 选中需要的完整段落或多个公式，点击 **Copy**。
2. 在 Word/WPS 的正文区域粘贴保留 `$...$` / `$$...$$` 的文本。
3. 选中粘贴内容，在 LocalReadTranslate 文档任务窗格点击
   **转换为原生公式**。

这一条路径继续使用后台的规范 LaTeX → Pandoc → 原生公式流程。不要把完整
混合段落粘贴进一个自带公式编辑框。

## 4. 验证范围

本次已验证：

- 用户提供的完整原公式经 **Copy** 后没有外层显示包装，两个矩阵行分隔仍在；
- 单公式的四类包装、矩阵括号和合法行距选项处理；
- 普通方括号、非法行距选项、正文与多个公式不会被误删或错误拆分；
- 翻译与朗读内部仍保留规范数学包装；
- 原始与兼容形式通过 DOCX/OMML 结构检查仍为两个 `2 × 1` 矩阵。

发布版本调整为 `1.15.9`，并合入远端已有的 ChatGPT 原始公式提取（`1.15.7`）
与 WPS `\bar` 简写兼容（`1.15.8`）修复。合并后的完整验证结果：

- `pnpm test`：`197/197 passed`，其中 core 与 Office 合计 `164`，选区与
  DOM 交互测试 `33`，包含新增的两项 Copy 按钮级回归；
- 完整 Python：`275 passed`、`17 subtests passed`，仅有一条已有的
  Starlette/httpx 弃用警告；
- Python 公式相关测试：`29 passed`；
- 真实 Pandoc 分别转换原始输入和新版剪贴板文本，得到相同的 LaTeX 回环
  结果，DOCX 中均为两个 `2 × 1` 矩阵、三个分式和两个点导数，未生成外围
  多余方括号。

DOM 模拟中的 Copy 按钮交互、自动化剪贴板文本与 DOCX 结构验证，都不等同于
在用户当前 WPS 版本的 GUI 里实际粘贴。
本记录不把它们表述成已完成 WPS GUI 端到端验收，也不承诺全部 LaTeX 命令
都被所有 Word/WPS 版本支持。宿主实测应在升级后的脚本上重新复制，再核对
没有额外方括号、空矩阵列，且公式仍可编辑。
