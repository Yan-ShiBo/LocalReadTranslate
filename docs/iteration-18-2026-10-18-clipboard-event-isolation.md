# Iteration 18：网页复制事件隔离与成功反馈

**版本：** userscript `1.15.11`；FastAPI 保持 `1.7.21`。
本轮修复网页脚本的剪贴板写入路径，不改变后端、文档插件宿主 API 或公式交换
格式。单个公式仍复制为裸 LaTeX，正文或多个公式仍保留规范包装；`1.15.10`
的公式边界修复继续保留。本次复制验证不需要启动模型或连接服务器。

## 1. 用户反馈与精确输入

用户确认已安装 `1.15.10` 并刷新网页，随后提供了完整
`data-d-component="math"` KaTeX DOM。其 MathML annotation 原始公式是：

```latex
B(x,\mathbf b)=\sum_{|\alpha|\le d_B}b_\alpha x^\alpha.
```

该 DOM 的精确提取结果正常：公式语义、上下标和原有字体命令均可保留，最终
单公式准备结果也是上述裸 LaTeX。因此，不能继续把这一次现象解释为用户
没有刷新，或把公式提取器生成了外层包装当成已经证实的原因。

精确输入保存在
[`tests/fixtures/reported-deepseek-barrier.html`](../tests/fixtures/reported-deepseek-barrier.html)。

## 2. 已复现的剪贴板改写路径

本机已安装的 Tampermonkey `5.5.1` 的 `content.js` 第 58 行显示，相关
`GM_setClipboard` 实现通过宿主文档的捕获阶段 `copy` 监听器与
`execCommand("copy")` 写入。更早注册的站点捕获监听器可以参与同一次宿主
复制事件，从而使准备好的文本与最终系统剪贴板不一致。

在隔离的 Chrome 复现页面中，给旧写入链路传入上面的裸公式，并模拟较早的
站点复制监听器，真实剪贴板最终得到 `\[...\]` 包装的公式；旧按钮仍显示
**Copied**。这证明只测试 LaTeX 函数输出，不能覆盖最终剪贴板是否被改写。

证据边界：已经复现的是这条事件干扰机制，**尚未捕获用户真实页面上的具体
监听器**，因此不把隔离实验写成已经直接观察到用户现场脚本的行为。

## 3. 新写入路径

网页选区与译文卡的 **Copy** 共用以下步骤：

1. 在浏览器提供可用原生接口时，优先调用并等待
   `navigator.clipboard.writeText`。它不派发宿主文档的 `copy` 事件。
2. 原生接口缺失或拒绝时，回退到工具条预先创建的同源 `about:blank` iframe，
   只在 iframe 自己的 document 中使用 `execCommand("copy")` 与复制监听器。
   不经过宿主页面的 `copy` 监听器，也不再调用旧的 `GM_setClipboard` 路径。
3. iframe 随工具条提前创建，在用户下一次点击 **Copy** 前已经存在，以便该
   次点击能给回退文档带来浏览器要求的临时用户激活；不能等原生写入失败后
   才临时创建 iframe。
4. 回退同时检查命令结果与实际复制事件的数据写入。执行完成后清空 textarea
   和监听器，恢复原选区与焦点；空 iframe 保留到工具条关闭，避免立即销毁
   文档取消浏览器尚待提交的剪贴板写入。工具条关闭时 iframe 一并移除。
5. 只有写入路径成功完成后才显示 **Copied**；等待时显示 **Copying**，失败
   显示 **Failed**，不把旧剪贴板冒充成新结果。

这不是全局剪贴板接管。普通 `Ctrl+C`、网页自己的复制按钮与站点原有复制
行为均不被修改。浏览器权限或用户激活限制仍然适用；回退也失败时会如实
报告失败。例如，权限提示长时间停留后才拒绝，临时用户激活可能已经过期，
回退可以明确显示 **Failed**，不保证所有权限策略下都能复制。此次事件隔离
针对网页脚本，文档插件现有复制格式和宿主链路不变。

## 4. 验证结果

本地完整回归结果：

- JavaScript：`253/253` 通过；
- Python：`305` 项测试及 `30` 项子测试通过，保留一条已有的
  Starlette/httpx 弃用警告；
- JavaScript 语法、catalog 同步检查及 `git diff --check` 通过。

新增回归覆盖精确 DOM、原生接口优先、等待异步成功、原生接口拒绝或缺失时
回退、用户激活和延迟提交模拟、重复复制以及工具条关闭后的资源清理；既有
公式包装、数学括号、矩阵、正文/多公式、翻译与朗读回归继续保留。

隔离的真实 headless Chrome 还执行了两条系统剪贴板检查：

| 写入路径 | `navigator.clipboard.readText()` 读回结果 | 宿主 `copy` 次数 | GM 写入次数 |
|---|---|---:|---:|
| 原生 Clipboard API 成功 | 精确匹配上述裸 `B` 公式 | 0 | 0 |
| 强制原生接口拒绝后的隔离文档回退 | 精确匹配上述裸 `B` 公式 | 0 | 0 |

两组真实浏览器检查还确认：普通 `Ctrl+C` 仍触发页面原有 handler 并产生该
页面的包装格式；随后再次点击插件 **Copy** 又得到裸公式。点击工具条外部
关闭工具条后，iframe 也被移除。这些步骤均包含实际剪贴板读回断言。

真实浏览器读回证明这两条路径的最终剪贴板内容，不只是 mock 参数正确；现场
辅助脚本位于 Git 忽略的本地目录，不作为已提交的 CI 工具或可复用公开脚本。
这些检查没有访问用户实际页面的监听器，也没有在 WPS GUI 中实际粘贴并转换
专业模式；两项限制不能被自动化测试通过替代。

1. 在 Tampermonkey 中把实际安装的脚本更新到 **`1.15.11`**，核对版本后刷新
   来源网页。仅更新项目文件、README 或 GitHub 页面不会替换已安装副本。
2. 选择目标公式，点击本插件浮动工具条的 **Copy**，等到 **Copied**。
3. 在 WPS 自带公式编辑框的 LaTeX 输入模式中粘贴，再转换为专业模式。
   若显示 **Failed**，不要把剪贴板中之前的内容当作本次复制结果。
4. 本次只是网页脚本更新，后台仍为 `1.7.21`。已使用该后台版本时无需重启，
   不需要启动 Ollama、加载模型或连接远程服务器。

版本支持全部 LaTeX 命令。
