# Iteration 20：单公式最终复制使用单行 LaTeX

**版本：** userscript `1.15.13`；FastAPI 保持 `1.7.21`。
本次修复 `1.15.12` 的回归：源码保留路径把物理换行带到了单公式最终剪贴板，
用户在 WPS 中粘贴后，一个公式被拆成多条。本次只调整单公式剪贴板边界，
不回退原始 TeX 保留、转置命令修复、字体参数分组或复制事件隔离。

## 1. 回归与准确输出

上一版正确保留了用户 KaTeX annotation 中的 TeX 命令和内部换行：

```latex
\mathcal L_{F_p}B
=\nabla B(x,\mathbf b)^\top f(x,p(x)).
```

但源码保存与公式编辑框粘贴是两个不同边界。用户明确反馈，`1.15.12` 最终
复制中保留的物理换行会在 WPS 中产生多条公式；因此，即使 TeX 命令完整、
Pandoc 生成的 OMML 相同，也不能证明多行文本可直接粘贴成一个 WPS 公式。

`1.15.13` 对这个单公式样例的最终剪贴板输出为：

```latex
\mathcal{L}_{F_p}B =\nabla B(x,\mathbf{b})^\top f(x,p(x)).
```

源码中的物理换行在最终复制处变成空格，`\top` 和已有数学内容仍保留；原始
annotation 与内部规范结果仍保存原换行。不是把整个输入、整篇正文或所有
公式统一压成一行。

## 2. 单行化的适用边界

| 内容 | 最终复制规则 |
|---|---|
| 没有正文的单个完整公式 | 单行裸 LaTeX，保留数学命令与内容 |
| 带公式的正文 | 保留规范数学包装和正文段落 |
| 一次复制多个公式 | 保留各公式与段落边界，不合成一行公式 |
| 源码、内部规范结果、翻译/朗读和文档写回 | 不应用剪贴板专用单行化 |

网页选区、网页译文卡、文档插件公式和译文复制沿用同一共享核心规则。文档
控制器的规范 `result.latex` 不被单行剪贴板覆盖；`clipboard_text` 才代表
实际复制内容。

## 3. 物理换行、矩阵命令与注释

- **物理换行**是文本中的 LF/CRLF，不是数学结构；单公式最终复制将其整理
  为单行，不能把相邻控制词与字母拼成一个新命令。
- **LaTeX `\\` 行命令**是矩阵、对齐环境中的公式结构，必须保留。即使整个
  剪贴板文本只有一个物理行，`\\` 仍能表达矩阵多行。
- **真正的 `%` 注释**必须连同注释内容安全去除；若只删物理换行却保留 `%`，
  原本下一行的有效公式会全部变成注释。
- **字面百分号**不能删除：`\%` 与 `\verb` 逐字内容中的 `%` 不是注释。
- **命令边界**必须保留：`\alpha% comment` 后接换行与 `x` 时，去注释后
  仍应是 `\alpha` 与 `x`，不能错误拼成 `\alphax`。

这些变换只服务于单公式最终复制。源码保留路径不会因此删除原始注释或
换行，正文与多公式也不会被全局空白压缩。

## 4. 升级与使用

1. 更新 Tampermonkey 中实际安装的脚本到 **`1.15.13`**，核对版本并刷新网页。
2. 只选中目标完整公式，点击本插件 **Copy**，等待 **Copied**。
3. 在 WPS 自带公式编辑框中粘贴并转换为专业格式；若该版本提供输入格式
   选择，选 LaTeX。不要寻找界面中不存在的切换，也不保证不同版本自动互认。
4. 样例应只占一个物理行，`\top`、`\mathcal{L}`、`\mathbf{b}` 均完整。
   矩阵中的 `\\` 应继续保留，不应手动删掉它们。
5. 文档插件使用更新后的共享脚本时，关闭并重新打开任务窗格。后台仍为
   `1.7.21`，无需为本次复制修复启动模型、连接服务器或重启同版本后台。

带正文或多个公式应粘贴到正文，再使用文档插件 **转换为原生公式**。网页
自身复制按钮和普通 `Ctrl+C` 不会被全局接管。仓库、GitHub Raw、Tampermonkey
已安装副本及 Greasy Fork 需要分别确认版本，不能仅凭项目文件已更新判断
浏览器已经使用新逻辑。

- Python：`306` 项测试与 `30` 项子测试通过，保留一条已有的
  Starlette/httpx 弃用警告。

回归覆盖完整 Lie-derivative fixture 的最终单行输出、原始/规范结果继续
保留换行、正文/多个公式保持段落，以及矩阵 `\\`、注释、字面百分号与
控制词分隔。既有 TeX 命令保留、字体分组、复制事件隔离和失败反馈测试继续
保留。DOM → 剪贴板 → Pandoc OMML 一致性测试增加了“剪贴板没有换行”的
断言并通过，规范原文仍有换行。

真实独立 Chrome 使用同一个完整 Lie-derivative fixture，分别验证原生
Clipboard API 与强制原生拒绝后的 iframe 回退。两条路径读回的系统剪贴板
都与上述单行输出**严格相等**，并通过
`doesNotMatch(/[\r\n\u0085\u2028\u2029]/)`；不使用 CRLF/LF 等价归一化来
掩盖残留换行。普通 `Ctrl+C` 仍走宿主 handler，第二次插件 Copy 正常，关闭
工具条后 iframe 清理也通过。

以上是本轮实际验证，不沿用 `1.15.12` 的结果作为通过证明。验证没有启动
本地后台或模型。

用户反馈确认了其 WPS 中的多公式现象；代码、DOM、剪贴板或 Pandoc 验证
仍不等同于修复后在用户当前 WPS GUI 中实际粘贴。本记录不宣称已完成该
GUI 验收，也不承诺所有 Word/WPS 版本接受全部 LaTeX 命令。
